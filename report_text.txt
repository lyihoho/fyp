[54] Abstract
[55] In many organizations, expense claims and receipts are manually reviewed, making the process time-consuming and prone to errors. The addition of duplicates or fraudulent submissions make it more difficult to identify all genuine receipts. This project proposes the development of an AI-powered claim receipt screening module that automates the verification process of receipt submissions. The framework utilizes a Deep Learning-based OCR architecture (PaddleOCR) alongside a parallel multi-criteria machine learning screening layer to detect structural template anomalies and duplicates natively.These details will be used to compare new submissions with past data to identify potential duplicates. Furthermore, a geometric validation layer will calculate structural aspects on submissions and compare with historical database to identify potential duplicates or template frauds, while a machine learning model will evaluate the similarity between receipts and identify any handwritten characters or potential aspects that may falsify the actual receipt information. These two layers run parallel to create a multi-criteria screening to eliminate fraud in a more robust manner. A confidence score or flag for review will be given to assist claim officers in making decisions more efficiently. Designed to function as a prototype with potential integration into actual claim systems, this project aims to enhance efficiency, reduce human errors while implementing AI-driven automation into real-world enterprise processes.

[142] 2.1.2 Text Extraction with PaddleOCR Deep Learning Framework
[143] Rather than relying on legacy, structural-character algorithms, the text extraction layer of this framework utilizes PaddleOCR (PP-OCR), a cutting-edge, deep learning-based optical character recognition pipeline designed to handle non-uniform text layout distributions. The extraction architecture operates as a decoupled two-stage neural network: a Differentiable Binarization Network (DBNet) for highly resilient local text-area boundary detection, followed by a Convolutional Recurrent Neural Network (CRNN) paired with Connectionist Temporal Classification (CTC) to decode text sequences directly from multi-planar document segments. This deep learning approach inherently handles the real-world smartphone capture noise such as curved brand headers, variable lighting gradients, and deep paper wrinkles—that typically causes traditional layout parsers to fail.
[144] The decision to employ pre-compiled PaddleOCR inference binaries over a custom, low-level tensor implementation (such as native PyTorch or raw TensorFlow) was a deliberate software engineering trade-off driven by environmental stability, local compute bounds, and compilation constraints. Deploying custom, lower-level deep learning models requires exact, rigid alignment between the local host's graphics processing hardware, native NVIDIA drivers, and specific runtime versions of the CUDA Toolkit and cuDNN libraries. In practical development environments where local GPU configurations exhibit varying compute capabilities or legacy media driver requirements, native tensor compilation frequently introduces catastrophic hardware initialization failures, memory leaks, or silent fallbacks to unaccelerated CPU processing blocks. By wrapper-interfacing with PaddleOCR’s highly optimized, pre-compiled deep tensor inference pipeline, the system safely unlocks high-precision character confidence scoring and absolute geometric bounding box tracking (left, top, width, height) on an active development machine without initializing unstable environmental dependencies or introducing runtime model initialization latency. This establishes an industrial-grade character ingestion baseline that securely feeds clean, structured metadata tokens to downstream machine learning anomaly models.

[159] 2.1.4 Relational Storage with SQLite and SQLAlchemy
[160] To secure data persistence and establish a high-performance relational storage tier, the framework implements a local data warehouse architecture using SQLite integrated with the SQLAlchemy Object-Relational Mapper (ORM). Rather than relying on volatile memory matrices, unindexed flat files, or high-overhead external server deployments, the system utilizes SQLite as a lightweight, disk-backed relational data engine. This architecture provides full ACID (Atomicity, Consistency, Isolation, Durability) compliance, ensuring that the structural layout features, extracted text tokens, and multi-criteria anomaly metrics for all transaction records are safely and permanently stored.
[161] The interface between the Python execution environment and the relational storage engine is managed via SQLAlchemy ORM, which abstracts raw SQL string queries into secure, strongly typed data models. Database connections are managed through a centralized session factory (SessionLocal), which isolates concurrent data execution paths.
[162] To safeguard database integrity during large-scale evaluation passes, the engine utilizes a progressive inline commit strategy block within its execution loops. Instead of holding a massive array of mutated rows in system memory and executing a single, risky global save operation at the end of a processing cycle, the application executes localized transactional blocks wrapped in strict exception handlers. If a specific row encounters an execution fault, layout exception, or schema validation failure, the session triggers an immediate database rollback. This architecture completely eliminates the risk of background memory leakage, data corruption, or silent pipeline crashes. Uncorrupted records are successfully committed progressively, ensuring high availability, auditable runtime traces, and reliable dataset scaling for enterprise compliance tracking.

[229] 2.5 Image Preprocessing
[230] Image preprocessing is an important stage in the system workflow as the quality of the input image directly influences the performance of the OCR extraction and machine learning modules afterwards. In this project, preprocessing was originally designed to utilize OpenCV to enhance text clarity and reduce noise typically present in real-world receipt images. The baseline process starts by converting the image to grayscale to simplify pixel information while retaining essential details. In traditional document pipelines, this is immediately followed by noise reduction using methods like Gaussian blurring to minimize background grain elements, followed by adaptive thresholding to generate a high-contrast binary image containing only flat black and white pixels. This is typically done to allow a clear separation between text characters and the paper background, even under poor lighting conditions. Additional standard steps, such as image resizing (upscaling) and geometric deskewing (straightening), are frequently incorporated to correct camera tilt distortions and standardize image dimensions to improve the consistency of OCR performance.
[231] However, detailed prototype testing within this project revealed that applying these universal, aggressive image-warping modifications introduces severe data corruption when dealing with non-uniform, crumpled smartphone receipt captures. Real-world expense submissions feature multi-planar document deformations, such as sharp physical pocket folds, non-linear paper waves, and variable shadow gradients. Forcing a global deskewing transformation based on standard straight line calculations miscalculates the median orientation angle when confronted with curved brand imagery or deep paper creases. This results in artificial canvas rotation that slants legitimate horizontal text blocks, scattering spatial coordinate tracks and turning readable headers into random text gibberish. Furthermore, implementing universal image resizing filters to upscale raw images blurs numeric character edges on wrinkled paper surfaces, causing text tokens to morph and leading to inaccurate transaction price extractions.
[232] Most importantly, aggressive binarization and smoothing filters completely erase the organic surface gradients, micro-shadows, and fold lines that define the physical receipt's unique condition. Because this framework explicitly targets these physical deformations as an invariant look-and-feel footprint to detect duplicate document scans (physical clone fraud), preserving raw canvas integrity is a core operational requirement. Consequently, to protect spatial coordinate heights and maintain stable baseline values for downstream anomaly calculations, the destructive image-warping preprocessing steps were discarded. The architecture instead implements a strict Coordinate-Preserving Native Ingestion Mode. The pipeline converts the raw color photos into standard, rich grayscale files to eliminate ambient table background color noise while keeping the original image frame dimensions completely unaltered. By letting PaddleOCR’s internal network manage minor text tilts natively, this approach ensures that every physical paper crease, wrinkle line, and font spacing gap remains fully intact as distinct, measurable database features for the anomaly detection module.
[233] 
[234] 2.5.1 Grayscale Conversion
[235] 
[236] The initial stage of the proposed verification pipeline establishes a non-destructive image ingestion framework designed to prepare raw user-submitted receipt photographs for text extraction while completely isolating the physical substrate from external noise. Traditional optical character recognition (OCR) systems frequently run input imagery through aggressive binarization masks, localized contrast adjustments, or thresholding layers to force pixels into absolute black or white states. While these methods sharpen flat text lines, they systematically destroy the subtle gray-intensity gradients that define real-world paper textures. Within this architecture, the input matrix is routed exclusively through a single-channel chromatic reduction layer using OpenCV to transform raw RGB data into a standardized grayscale plane.
[237] 
[238] By avoiding destructive thresholding filters, the pixel-intensity variations caused by physical document mutations—such as sharp pocket creases, paper waves, surface folds, and organic crumple patterns—are preserved as distinct micro-shadow signatures. This preservation is a core structural requirement for the overall system framework; because the downstream anomaly detection engine uses these unique physical substrate deformations as a behavioral fingerprint to detect duplicate document scans (physical clone fraud), the ingestion module must keep the raw visual footprint of the paper completely unaltered. Consequently, this layer eliminates ambient background coloration and wood grain table noise while securing the physical layout signatures of the paper medium for downstream profiling.

[245] 2.5.2 Watermark Removal for Synthetic Templates
[246] During the development and testing phases, synthetic receipt templates were generated to augment the training dataset. However, these synthetic assets frequently contain decorative light watermarks, background patterns, and grid lines that interfere with character boundary tracking. To address this, a targeted binary split thresholding technique is applied. The input image is converted to grayscale, and a definitive binary threshold value of 150 is applied. Any pixel lighter than 150 (representing the light watermark lines) is flatlined to pure white (255), while the darker machine-printed receipt text is preserved. This isolates the character tokens, eliminates background noise, and significantly improves OCR character extraction accuracy on synthetic templates.

[249] 2.6 Text Extraction and Data Parsing Layer
[250] Once the input image is converted into a stable, high-fidelity grayscale file, the asset is passed directly into the text extraction and data parsing module to decode the textual payload and map the underlying physical layout structure of the receipt medium. The processing pipeline executes a deep-learning character extraction sweep using the pre-compiled PaddleOCR engine. Instead of generating a disordered, unstructured string array or a raw text dump, the neural network infrastructure outputs a highly structured dataFrame containing precise geometric bounding box coordinates (left, top, width, height) alongside localized character classification confidence matrices for every single registered word token across the multi-planar surface canvas.
[251] Operating at this granularity allows the ingestion script to completely isolate true receipt text from external visual artifacts. Empty typographic spaces, structural layout padding, and low-confidence unreadable pixel fragments are algorithmically filtered out during this initial processing phase. By capturing the absolute spatial coordinates of each character bounding box natively via the deep learning inference path, the system ensures that the relative positioning of every word remains fully preserved. This establishes an unalterable spatial and textual coordinate track that safely isolates valid horizontal text lines, preparing the structured data tokens for downstream multi-criteria compliance verification and deterministic gate mapping.
[252] 2.6.1 Filtering Design for Empty Extraction
[253] To protect data warehouse purity and safeguard downstream machine learning models from data distortion, the module implements a deterministic Ingestion Gatekeeper block immediately following the raw data sweep. Document images that suffer from extreme degradation, such as catastrophic thermal ink fading, motion blur, or severe image cropping, often fail to yield readable text tokens.
[254] The gateway evaluates the incoming document against three explicit baseline constraints:
[255] Total Token Check: The image must contain a minimum of 5 valid text tokens (Length(Data)  5).
[256] Structural Emptiness Check: The extracted data matrix must not be entirely empty (Data.empty = False).
[257] Average Confidence Quality Gate: The mean OCR character confidence score must not fall below a baseline threshold of 25.0% (Mean(conf)  25.0%).

[272] 2.6.4 Multi-Criteria Feature Collection
[273] Simultaneously, during the text extraction sweep, the parsing script executes a parallel data collection track to isolate four distinct, independent look-and-feel variables that mathematically define the receipt's physical layout signature. Saving these layout metrics ensures that the system does not rely on text strings alone. If text fields become unreadable due to ink fading or heavy creases, these underlying spatial metrics persist with high structural stability, allowing the system to flag identical document layouts even when character recognition drops out. The four extracted features include:
[274] Word Count: Logs the absolute volume of valid character tokens registered across the canvas frame, serving as a baseline check for text layout density.
[275] Layout Density Ratio: Computes the cumulative surface area of all valid word bounding boxes relative to the global image pixel plane (Width  Height). This ratio captures the precise typographic ink footprint of the merchant receipt, remaining completely invariant regardless of camera distance or sensor resolution changes:
[276] 
[277] Vertical Alignment Variance: Measures the statistical variance of the raw top vertical coordinate vectors (top) across all extracted words. On a heavily crumpled, wrinkled, or folded piece of paper, individual word baselines naturally bounce up and down erratically, generating a high vertical variance signature that uniquely identifies that specific deformed sheet of paper.
[278] Character Spacing Variance: Programmatically tracks layout changes across the horizontal processing grid. The script sorts the entire data matrix chronologically by its spatial positions (top, then left) and evaluates the horizontal gap differentials (left) between contiguous tokens across the sheet. The statistical variance of these gaps (Var(left)) defines the distinct layout margins, font justifications, and text-column spacing configurations applied by the merchant's print engine, providing highly sensitive telemetry for detecting structural text-shifting or clipping anomalies.
[279] Line count: Represents receipt length. This is achieved by extracting total lines of the captured receipt, which will then be used for model training to identify normal length range for a standard receipt, making the system more intelligent in identifying anomalous entries.
[280] Aside from the metrics needed for model training, some other metrics are extracted or calculated for processes like math checking, non-receipt image flagging, length checking, and so on. The required metrics are calculated as below:
[281] Average OCR confidence: This is extracted directly from PaddleOCR after scanning each image. As the OCR engine outputs a confidence score for each run, an extremely low score means the machine cannot successfully read text from the image, indicating non-receipt entry that needs to be blocked without undergoing the remaining pipeline.
[282] Unreadable gate flag: This flag is switched to true if empty data is obtained from an OCR scan. This is achieved by checking the length of text read, whether the data is empty, or the mean confidence is less than 0.82.
[283] Full raw text: This records the full text scanned by the OCR engine. This can be used to check if it has high similarity with any existing records to identify duplicate fraud.
[284] 2.6.5 Checking for Potential Physical Template Fraud and Duplicates
[285] In this layer, the system also checks for potential duplicate fraud by utilizing Levenshtein’s distance calculation and ORB matching. The full raw text extracted in the previous step is used in this stage by comparing it with raw text from past records to identify similarity. If the similarity rate gets more than or equal to 95%, the entry is flagged as a textual duplicate to suggest text reuse fraud. 
[286] At the same time, physical template fraud is identified by applying ORB similarity check. Feature descriptors are assigned by placing 1500 ORB points on each image, which are then saved in the database after being compiled into base64 values. Every time a new entry occurs, each feature descriptors are decrypted to be compared with the uploaded image by using BruteForceMatcher (BFM). If the similar orb count exceeds 120, the image is flagged with physical template fraud, suggesting duplicate templates with different content.
[287] There are some cases where final flags are given without proceeding with the rest of the pipeline. In this layer, the system identifies potential physical fraud or duplicates flagged in the previous stage and decides on next steps that the entry should undergo. The labels that can be flagged in this phase are:
[288] Physical Template Fraud: An entry will get this label if it exceeds the threshold during ORB matching, but passes the duplicate checking using extracted full raw text.
[289] Standard Duplicate: An entry will get this label if it exceeds both the similarity threshold for ORB matching and raw text checking.
[290] Text Data Reuse Clash: An entry will get this label if it has high text similarity with existing records but does not exceed ORB matching similarity threshold.
[291] If any of these flags are given to an entry, it skips all of the next stages like multi-criteria checking with machine learning and ends the pipeline directly. If the entry meets none of the filtering criteria, it will get a temporary “pending” label and proceed to the remaining stages of the pipeline.

[293] 2.7 Model Training
[294] The model training phase serves as the fundamental learning architectural framework of the automated receipt compliance system. Unlike traditional signature-based detection mechanisms that rely on rigid, hard-coded rules or regular expression text patterns, this system utilizes unsupervised machine learning to dynamically establish an operational baseline of "authentic document behavior." By leveraging an unsupervised architecture, the system completely removes the necessity for manual data labeling or manual classification of fraud vectors, allowing it to organically digest multi-dimensional features from a centralized database warehouse and map out a tight, mathematical distribution cluster representing legitimate point-of-sale transactions.
[295] The primary objective of this training mechanism is to construct a highly resilient baseline that models the standard physical geometry, spatial constraints, and internal line alignment of genuine receipts. The system extracts raw spatial values like character bounding box layouts, vertical row splits, text density, and pixel ink-to-whitespace ratios. These aspects are then modelled collectively. This comprehensive baseline training acts as the analytical anchor for the system, ensuring that when a new receipt is introduced during runtime, the system evaluates it not against arbitrary criteria, but against a mathematically mapped distribution derived from a rich, historically validated database of clean transactions.
[296] 2.7.1 Machine Learning Baseline Framework
[297] To establish a system capable of flagging sophisticated document manipulation, the training phase must first synthesize a comprehensive statistical profile of a standard business receipt. Receipts generated by point-of-sale (POS) terminals follow predictable structural rules determined by industrial thermal printers, commercial layout software, and alignment grids. However, minor variations in paper quality, text line lengths, and merchant branding introduce a level of natural data noise that hard-coded systems cannot handle. The machine learning baseline framework overcomes this limitation by treating every authentic receipt as a multi-dimensional data point within an open feature space, observing how these attributes naturally cluster together when no tampering is present.
[298] During this phase, the training script establishes a secure database connection to the local SQLite data warehouse and pulls the entire historical pool of parsed entries. This historical pool consists of clean, verified receipts that represent the normal operating boundaries of typical business expenses. By aggregating these rows into a unified master matrix, the training framework exposes the underlying machine learning algorithms to a wide variety of legitimate layout styles. This ranges from short, single-item fast-food slips to long, multi-line grocery invoices. This comprehensive exposure allows the system to learn the natural elasticity of genuine receipt structures, setting up a defensive barrier where authentic variations are accepted but true structural anomalies stand out instantly.

[315] 2.7.3 Isolation Forest Training
[316] Following feature standardization, the system executes the core training of the anomaly detection engine using the Isolation Forest algorithm. Traditional anomaly detection models attempt to profile normal data zones and flag anything outside them, which is a technique prone to high false-positive rates on complex, skewed receipt layouts. The Isolation Forest flips this paradigm by explicitly isolating anomalies instead of profiling normal structures. The mathematical theory relies on the principle that anomalies possess distinct structural patterns, irregular alignment spreads, and highly unusual data attributes. Consequently, when structural data points are passed through a collection of randomly generated decision trees, these anomalous vectors are carved away from the main crowd very early in the tree-splitting process, resulting in a much shorter path length from the root node to the terminating leaf node.
[317] The training architecture trains two distinct Isolation Forest ensembles to enforce a strict multi-criteria compliance evaluation:
[318] Look & Feel Forest (look_feel_forest.pkl): Configured with 100 decision trees and a contamination parameter of 5%, this model constructs a forest dedicated to mapping macro layout densities and document aspect boundaries. It calculates the isolation path speeds of global document shapes to ensure the canvas layout matches a standard POS receipt.
[319] Structure & Format Forest (structure_forest.pkl): Also running an ensemble of 100 decision trees, this model is hyper-focused on internal line alignment grids, learning the normal vertical variance drop-off patterns of genuine receipts. It isolates documents where text blocks have been artificially shifted or inserted, catching manual layout manipulations.
[320] Upon successful completion of the training iteration, these models serialize their node decision rules natively. They are stored as compressed binary files inside a protected directory (/models/), providing instant, lightweight access for prediction engines without needing to recompute tree branches on every execution run.

This design ensures that unreadable records remain securely logged for system audit tracing without wasting CPU processing cycles on unresolvable document layouts.
[331] 2.8.3 Algorithmic Execution of Main Compliance Metrics
[332] For records that are readable, the engine activates its four specialized evaluation pipelines to calculate independent compliance scores, mapping the results directly to their respective database columns:
[333] Look & Feel Score (score_look_feel):
[334] The engine converts the target's raw global dimensions (layout_density_ratio, receipt_length, and aspect_ratio) into a unified numpy array. It applies the frozen mathematical adjustments from look_feel_scaler.pkl and feeds the result to look_feel_forest.pkl. The model evaluates the isolation path lengths across its decision trees, and the resulting raw outlier score is mathematically calibrated into a clean, intuitive percentage value from 0% to 100%.
[335] Structure & Format Score (score_structure_format): 
[336] This metric targets internal text line alignments. The engine extracts raw coordinate distributions via num_lines and vertical_alignment_variance, standardizes them using structure_scaler.pkl, and runs them through structure_forest.pkl. If line-spacing numbers show unusual shifts or sudden vertical jumps like typical indicators of digital cut-and-paste tampering or heavy document creasing, the model flags the variance and drops the compliance score proportionally.
[337] Content Accuracy Score (score_content_accuracy): 
[338] This metric enforces an automated context-aware financial audit layer, handles duplicate submission detection, and applies a rule-based Conditional Penalty Metric. The system pulls the extracted metadata fields (merchant, date, and total_amount) and defines explicit Boolean tracking flags for data completeness. 
[339] To protect genuine receipts that suffer from minor single-field OCR typos from being completely destroyed by false alarms, the system applies gentle deductions for a single missing component. However, if a severe document dropout occurs, the system triggers a cascade penalty combination:
[340] If both the total amount and transaction date are missing at the same time, the score will undergo a heavy deduction of 30% to reflect a high-risk compliance asset.
[341] If both the store name and the total amount are missing simultaneously, the score is penalized by 25%.
[342] If both the store name and the transaction date are not extractable, a deduction of 20% is applied.
[343] If the math valid flag is generated as 0, the content accuracy score is penalized directly to 30% to drag the composite score below the approval threshold and force a manual review.
[344] Text Integrity Score (score_text_integrity): 
[345] This pipeline focuses entirely on local character properties, handwriting noise, and image degradation tracking. Industrial thermal printers output text along uniform grids with consistent letter spacing, resulting in a low variance. When handwritten notes, signatures, pen marks, or heavy image distortions are present, they introduce irregular ink strokes. The engine detects this by tracking character confidence and the character_spacing_var column. If the average OCR character confidence falls below an 82.0% baseline, the score is penalized exponentially based on the depth of the text degradation. Additionally, a massive spike in character spacing variance indicating non-machine text triggers a 15.0% reduction to isolate manual tampering noise.
[346] 2.8.4 Pipeline Verdict Logic and Database Synchronization
[347] After calculating the four independent metrics, the engine passes the transaction record through a multi-tiered corporate governance switchboard to assign a definitive compliance label. Rather than evaluating claims solely on a linear composite average, the system implements short-circuit logic gates to isolate high-risk structural and textual anomalies before applying automated financial clearance. The execution loop routes entries based on the following hierarchical validation matrix:
[348] APPROVED FOR REIMBURSEMENT: 
[349] Reserved strictly for pristine documents that clear all deterministic fraud gates and achieve a safe baseline score distribution of more than or equal to 75.0%. This indicates that the asset matches the authentic historical baseline across all physical, structural, and content metrics, allowing for secure, automated financial processing. 
[350] SELECTED FOR MANUAL REVIEW: 
[351] Applied as a robust risk-mitigation fallback layer. Under standard conditions, this captures borderline entries with a composite score between 50.0% and 75.0% that display minor spatial, typographic and math alignment noise. Crucially, this gateway serves as an executive fail-safe for physical template duplicates: if a document triggers an initial PHYSICAL TEMPLATE FRAUD ingestion alert but physical capture noise (such as shadows or perspective shifts) degrades the local keypoint alignment down to a weak match, the pipeline completely blocks automated clearance. Any pre-flagged template warning calculating a composite score greater than or equals to 60.0% bypasses the standard approval track and is routed directly to human auditors to prevent high-scoring, layout-tampered assets from auto-clearing.
[352] REJECTED (SUSPECT IMAGE OUTLIER): 
[353] Triggered when severe visual anomalies, failed math validation checks, or duplicate transaction clones are discovered, locking down high-risk claims, leading to a composite score of less than 50%.
[354] REJECTED (IMAGE UNREADABLE - PROMPT RE-UPLOAD): 
[355] Triggered instantly at the initial ingestion gatekeeper if the document yields fewer than 5 text tokens or falls below the 25.0% mean character confidence threshold. This cleanly short-circuits all downstream machine learning scoring to preserve data warehouse purity. 
[356] REJECTED (SUSPECT CORRUPT TEXT MATRIX): 
[357] Assigned downstream if local character tracking or line-alignment scores drop below critical limits (e.g., text integrity score < 25.0 or structure score < 20.0). This isolates documents suffering from extreme digital distortions or non-machine text modifications. 
[358] REJECTED (DUPLICATE/NON-RECEIPT): 
[359] Enforced instantly if the deterministic historical cross-check detects an absolute data or structural clone. If a matching transaction total, date, and merchant string collision is identified, or if visual alignment checks drop to zero, the content accuracy score is penalized to 0.0%, and the system issues an explicit duplicate rejection.
[360] The final step of the inference cycle is database synchronization. The engine updates the specific database row in receipts.db, permanently mapping the finalized compliance scores and corporate labels next to the original text attributes. This finishes the execution cycle and prepares the data for downstream front-end platform display.

[423] Furthermore, the prepended-digit pen tampering check on a tampered receipt dropped the Content Accuracy score to 30%, forcing the composite score down to 63.1%. Since this score is below the updated 75% threshold, the tampered document was successfully intercepted and routed to manual review.
[424] This architectural combination of early-stage gate intercept loops and continuous machine learning scoring ensure the system preserves higher fraud detection recall while maintaining high-auto-approval precision for users or employees.
[425] 3.2.4 Analysis of Pipeline Edge Cases and System Limitations
[426] While the dual-engine duplicate detection and machine learning scoring framework is highly resilient under standard test distributions, it is critical to evaluate the system behavior under extreme edge cases and operational boundaries to verify its real-world compliance integrity. There are five key edge cases identified and analyzed below:
[427] 1.  Recaptured Duplicate under Optical Degradation
[428] When a duplicate receipt is retaken under extreme optical degradation such as heavy motion blur, sever lens distortion or low-light glare, both the Levenshtein text similarity and the ORB keypoint geometric matcher may fail to trigger their respective duplicate gates. In this scenario, the textual similarity falls below the 95% clone threshold due to OCR character recognition dropouts while the blurred surface edges prevent ORB descriptors from aligning above the 120-match threshold.
[429] To mitigate this bypass risk, the system utilizes its continuous machine learning scoring metrics as a secondary safety net. The optical degradation directly drops the mean OCR confidence score below the 82% baseline. This drop triggers exponential penalties in the Text Integrity and Structure & Format scores. As a result, the composite score falls below the 75.0%75.0% threshold, successfully intercepting the duplicate claim and routing it to the database with a verdict of SELECTED FOR MANUAL REVIEW or REJECTED (IMAGE UNREADABLE - PROMPT RE-UPLOAD).
[430] 2.  Physical Template Collisions on Unique Transactions
[431] When two different employees submit unique receipts printed by the same franchise merchant (e.g. two different customers buying different items on different days at the same store), they share the exact same printed thermal paper template which have identical brand headers, layout margins, logo coordinates, and footer lines. This template sharing triggers a high ORB layout match count with matching keypoint shapes across the paper substrate.
[432] However, because the purchased items, time, and total amount is unique, the extracted text content differs. The Levenshtein text similarity remains low with scores below the 95% duplicate threshold. The system detects this collision with is_physical_duplicate = True but is_textual_duplicate = False, and routes the record to the database with a verdict of REJECTED (PHYSICAL TEMPLATE FRAUD). In high-security corporate auditing, flagging identical templates is functionally correct as it prevents digital layout fraud where a real receipt layout is scanned and edited with fake text and enforces strict compliance, requiring the employee to submit alternative validation proof like transaction history of bank statements to clear the submission manually.
[433] 3.  OCR Character Hallucination
[434] Under faded printing or scanner glare, OCR engines are prone to character transpositions on numerical values like reading a total of 10.50 as 1O.5O or RM5.00 as RMS.00. If uncorrected, this would cause the regular expression parser to miss the transaction total or flag a false math valid mismatch.
[435] The framework addresses this limitation through a custom string cleaning step that automatically repairs common character hallucinations on numeric boundaries. Furthermore, any severe OCR corruption that cannot be corrected is flagged by the average confidence tracker. If the OCR confidence drops, the system applies text integrity penalties, routing the distorted document to manual review to prevent faulty financial records from being auto-approved.
[436] 4.  Non-standard Document Formats
[437] Corporate expense submissions often include non-standard documents that do not follow structured point-of-sale layout formats, such as handwritten carbon paper invoices, transportation tickets or public transit slips. These documents lack clear vertical column alignments and exhibit atypical width-to-height dimensions.
[438] When processed, these non-standard formats are flagged by the Look & Feel Isolation Forest model (look_feel_forest.pkl). Because their layout density ratios and aspect ratios fall far outside the normal distribution cluster of pre-printed thermal receipts, the model identifies them as spatial outliers (anomalies). The Look & Feel score drops, pulling the overall composite score down and routing the non-standard documents to human audit logs. This ensures that the system remains specialized for thermal receipt parsing while retaining the ability to intercept atypical claims.
[439] 5.  Temporal Boundary Collisions (Same-Day Visits)
[440] A common edge case in business expenses is when an employee legitimately visits the same merchant twice on the same day such as buying a client lunch and afternoon coffee at the same restaurant. A simple metadata-based check on just the same date, merchant, and similar total would flag this as a duplicate submission.
[441] This framework avoids this false positive because the receipts feature different transaction timestamps, distinct item lists, and unique order IDs. The Levenshtein similarity compares the entire raw text block, falling below the 95% clone threshold due to these distinct details. As long as the receipt photos are physically distinct (yielding low ORB matches), the system correctly identifies them as separate transactions and auto-approves both claims, maintaining operational efficiency.
